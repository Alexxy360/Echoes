# Zamykanie niepewnych decyzji moderatora — CK-05d.2c.1

Stan: backend i istniejący przepływ iOS wiadomości zaimplementowane i odebrane lokalnie. Poprawka poprzedza panel zgłoszonych zdjęć2d. Nie aktywuje usług ani uprawnień. [Pełny plan migracji](PLAN_MIGRACJI_CLOUDKIT.md).

## Potwierdzony problem

W obu koordynatorach wykonano lokalnie recover(not-applied), a potem opóźnione decide tego samego UUID w nadal ważnym receipt. Decyzja została przyjęta, powodując ukrycie wiadomości albo odrzucenie zdjęcia. Odczyt był prawdziwy w chwili wykonania, lecz nie stanowił dowodu ostatecznego niewykonania. Starszy GatewayReportReviewJournal traktował notApplied jako resolved i dopuszczał ACK. Nowy panel zdjęć nie może kopiować tego zachowania.

## Backend i HTTP

- Dwie oddzielne domeny mają minimalne tabele retirement. Jawne retire własnego decisionID/contentHash/verdict w tej samej transakcji SQLite odczytuje znany wynik albo utrwala barierę nonce. Decide sprawdza ją w swojej transakcji, bez await przed efektem. Zamknięcie nie zamyka całego raportu. Nowa inspekcja i inny UUID nadal mogą rozstrzygnąć dostępny raport.
- Osobne POST `/v1/moderation/reports/retire` i `/v1/moderation/avatar-reports/retire` mają dokładnie reportID, decisionID, verdict, contentHash. Operator pochodzi ze zweryfikowanej sesji. Pozostają obecne role/limity/body512B, deadline i kontrola po IO/checkpoint/finalizerze. Odpowiedź retire dopuszcza wyłącznie retired/confirmed/superseded. Recover dodatkowo odczytuje retired, bez tworzenia bariery lub ponawiania decyzji.
- Znana własna decyzja daje confirmed z tą samą revision; inna znana decyzja daje superseded. Oba wyniki nie cofają efektu. Bez historii tworzymy retired: blokadę przyszłego wykonania tej próby, **bez twierdzenia, że wcześniej nigdy się nie wykonała**. Utrata ACK nie zmienia identyfikatora; dokładne ponowienie nie przesuwa istniejącego terminu.
- Marker zawiera hash moderatora, decisionID, hash pełnej intencji, opcjonalny hash właściciela raportu do erasure oraz czasy. Bez reportID, tekstu, powodu, zdjęcia, GPS, tokenu lub kopii profilu. Hash intencji zobowiązuje także reportID i domenę. Do256 zachowanych wpisów na moderatora i4096 na domenę; niewyczyszczone wygasłe wpisy mogą konserwatywnie zajmować limit.
- Logiczna ważność do30dni od pierwszego aktywnego retirement; sprzątanie najwyżej100 wygasłych wpisów na domenę w przebiegu maintenance i najbliższy alarm. Nie obiecujemy fizycznego usunięcia dokładnie w terminie bez odbioru działającego hostingu/alarmów. Po wygaśnięciu i jawnym nowym działaniu może powstać nowy marker; nie jest to wieczna historia UUID. Dawna receipt90s pozostaje nieważna.
- Erasure moderatora lub znanego właściciela raportu usuwa związane markery w istniejącej transakcji. Minimalne markery dla nieznanego raportu nie mają powiązania z jego właścicielem i wygasają zwykłą ścieżką. Usunięte/wyłączone konto lub raport nie może ominąć bariery przez stary receipt.

## Istniejący iOS wiadomości

1. NotApplied jest obserwacją nieostateczną: nie tworzy terminalnego result handle, nie daje ACK i nie zwalnia miejsca na nową decyzję. Readonly recovery nadal jest dostępne.
2. Starszy zapis resolved/not-applied odczytujemy jako dispatched z tymi samymi metadanymi, decisionID i lokalną revision; sam odczyt nie naprawia, nie przepisuje ani nie usuwa zapisu.
3. Jawne zamknięcie przechwytuje dokładną intencję. Journal zapisuje retiring **przed tokenem i API**, a host sprawdza konto, iCloud, Apple, rodzica, foreground, flagę i dzierżawę przed/po każdym await. Nie ponawia decide, nie tworzy nowego UUID i nie odtwarza materiału. Timeout/utrata ACK pozostawia retiring do ręcznego recovery lub jawnego ponowienia zamknięcia.
4. Terminalny wynik nie może zostać osłabiony do not-applied lub zastąpiony innym wynikiem. Jego trwałe metadane mogą po restarcie utworzyć świeży lokalny handle do ACK, również po wygaśnięciu historii serwera. Stary handle nie usuwa nowego wpisu. To historyczny wynik tej próby, bez odtwarzania prawa do decyzji lub treści.
5. UI mówi „Decyzja nie jest potwierdzona. Może jeszcze zostać zapisana.” Osobny anulowalny formularz zamknięcia wyjaśnia przyszłą blokadę i brak cofania wcześniejszych zmian. Jeden enum przechowuje rozłączne potwierdzenia decyzji/zamknięcia, wyłącznie jako metadane. Tło i zmiana intencji odcinają stary formularz. Dostępność: Form z przewijanymi akcjami także przy AX XXXL.
