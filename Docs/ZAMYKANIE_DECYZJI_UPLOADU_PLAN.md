# Zamykanie niepewnych decyzji o uploadzie — CK-05d.2c.2

Stan: 21 listopada 2026, zaimplementowane i odebrane lokalnie według poniższego planu. Obejmuje oddzielny panel approved/rejected nowych uploadów. Poprzedni etap [2c.1](ZAMYKANIE_NIEPEWNYCH_DECYZJI_MODERATORA.md) obsługuje decyzje zgłoszeń. Nie aktywowano usług. [Dowody i SHA](evidence/upload-review-retirement-local-tests.json).

## Problem i zachowany zakres

Audyt konkretnego lokalnego edge/Authority/Runtime/SQLite wykazał recover(not-applied) → opóźnione decide(rejected) → recover(confirmed). W tym samym czasie publishedVersionID pozostał null: ocena nie publikuje zdjęcia za autora. Starszy journal uznawał notApplied za resolved, a host zwalniał lokalną barierę zdjęcia. Nieostateczny odczyt nie mógł dawać takiej gwarancji. Zapisany wcześniej plan obejmował kolejno: rejestr, atomową barierę, HTTP, journal/ochronę publikacji, UI i odbiór. Wszystkie te części sprawdzono lokalnie.

## Rejestr i transakcja efektu

Osobna prywatna tabela SQLite avatar_review_decision_retirements_v1 zawiera hash moderatora, decisionID, hash intencji, hash właściciela zdjęcia oraz czasy. Intencja zobowiązuje domenę, moderatora i pełne accountID/requestID/versionID/generation/reviewRevision/decisionID/verdict. Nie zapisujemy osobnych pól ID właściciela/wersji/request, obrazu, URL, receipt, tokenu lub danych profilu.

AvatarPolicyState.review odczytuje barierę **we własnej transakcji przed zmianą moderation_state/revision i ready**. Sam check przed claim lub w koordynatorze nie wystarcza: test wstrzymuje starsze żądanie już po trwałym claim, zamyka próbę przez drugi koordynator i dopiero wtedy zwalnia stare żądanie. Efekt nie następuje. Świeża inspekcja i nowy UUID nadal mogą legalnie rozstrzygnąć pending upload.

RetireReview odczytuje znany wynik lub utrwala marker w jednej transakcji. Znane confirmed/superseded nie są cofane; brak rozstrzygającej historii daje retired. Retired blokuje późniejsze wykonanie tej próby, ale **nie dowodzi, że żadna wcześniejsza zmiana nigdy nie nastąpiła**. Nie odrzuca całego joba, nie przywraca poprzedniego zdjęcia i nie publikuje za autora. Po sync wynik jest ponownie sprawdzany. Niespójność/utrata ACK zachowuje niepewność klienta do ręcznego odczytu.

Nowe retire wymaga synchronicznego, świeżego authorize() === true oraz aktywnego konta moderatora. Istniejący wewnętrzny review zachowuje dotychczasowy model zaufanych grantów serwisowych; jego publiczny koordynator weryfikuje sesję/rolę przed wywołaniem i po await. Nowa bariera jest egzekwowana także w tym niższym review. Nie nadano żadnego nowego grantu lub roli.

Do256 zachowanych markerów/moderatora i4096 globalnie, logiczna ważność30dni od pierwszego aktywnego zamknięcia. Retry nie wydłuża terminu. Do100 wygasłych wpisów sprzątanych w przebiegu maintenance, z najbliższym alarmem; niewyczyszczone wygasłe wpisy konserwatywnie zajmują limit. Nie deklarujemy dokładnego fizycznego terminu usunięcia bez odbioru hostingu/alarmów ani wiecznej historii nonce. Erasure moderatora lub wskazanego właściciela usuwa związane wpisy w istniejącej transakcji wyłączonego konta. Stara receipt90s pozostaje nieważna po wygaśnięciu markera; cofnięty zegar odmawia operacji.

## HTTP i iOS

POST /v1/moderation/avatar/retire ma dokładnie siedem pól recovery, natywny bearer, obecne flagi/role/limity512B/30 żądań na minutę i deadline/drain. Obsługiwane wyniki retire to tylko retired/confirmed/superseded z odpowiednią revision. Recover dodatkowo odczytuje retired i pozostaje readonly. Checkpoint/finalizer ponownie kontrolują konto i rolę. Domyślne ustawienia usługi pozostają wyłączone/puste. Odpowiedzi błędów nie zawierają treści lub prywatnych pól.

GatewayAvatarReviewJournal zachowuje ten sam zakres Keychain i zamknięty format v1. Dawny resolved/not-applied jest odczytywany jako dispatched z tym samym UUID i lokalną revision, bez zapisu podczas odczytu. NotApplied nie daje ACK i nie zwalnia miejsca na nową decyzję. Trwały retiring powstaje przed pobraniem tokenu i HTTP. Nie ma automatycznego retire, resubmit decide, nowego ID lub odtwarzania obrazu/receipt. Terminalnego wyniku nie można osłabić. Przy ponownym connect terminalny zapis otrzymuje świeży lokalny ACK handle; starszy handle jest odrzucony, a nowe uprawnienie do decyzji nie powstaje.

Host emituje resolved do GatewayCommunityAvatarHost wyłącznie dla trwałego terminalnego wyniku. Niezależna kontrola odbiorcy ignoruje resolved(notApplied), nawet od lokalnego adaptera. Not-applied/retiring i restart zachowują lokalne odcięcie mapy/profilu/wiadomości/własnego edytora. Terminalna odpowiedź dopuszcza **nowy chroniony odczyt**, nie przywraca starych pikseli lub zgody/publikacji autora. Zmiana native/iCloud/Apple/konta/rodzica/foreground, erasure i spóźnione odpowiedzi nadal odcinają poprzedni scope.

AvatarReviewView ma jeden enum rozłącznych potwierdzeń decyzji/zamknięcia. Zatwierdzenie/odrzucenie zdjęcia zachowuje osobny alert i rzeczywisty bieżący obraz. Zamknięcie ma osobny anulowalny Form, wyjaśniający skutek bez cofania/publikowania. Metadane w State nie zawierają pikseli. Tło i zmiana pending zamykają stary formularz. Nieostateczny wynik mówi „Decyzja nie jest potwierdzona. Może jeszcze zostać zapisana.” Odtworzony retiring pozwala ręcznie sprawdzić wynik lub jawnie ponowić zamknięcie.
